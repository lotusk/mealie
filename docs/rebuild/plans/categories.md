# Categories endpoint migration implementation plan

## Objective and boundaries

Move the complete authenticated `/api/organizers/categories` endpoint group from FastAPI to the existing Spring Boot backend and route it through Caddy. Preserve current HTTP behavior, group isolation, database effects, and notifications on both SQLite and PostgreSQL. Java must execute category reads and writes itself against the shared database; Python remains responsible for Alembic and notification delivery through the existing signed event bridge.

This document is the implementation handoff. No feature code has been written as part of preparing it. Follow the repository's `AGENTS.md`. Do not change the database schema, frontend API/types, locale files, unrelated organizer APIs, or public explore routes. No code generation is needed unless implementation unexpectedly changes Pydantic schemas (none is planned).

## HTTP contract

All paths below are relative to `/api/organizers/categories`. All require authentication, including reads. The actor's **group**, not household, defines category scope; administrators do not bypass it. Reads are allowed without `canOrganize`; POST, PUT, DELETE and merge require it, including for administrators. Use existing JWT/API-token/cookie authentication and preserve integration IDs.

| Method/path | Success | Exact response fields |
| --- | --- | --- |
| GET base | 200 | Pagination envelope with `items` containing `id`, `groupId`, `name`, `slug`, `recipeCount` |
| POST base | 201 | CategoryOut: `name`, `id`, `groupId`, `slug`, `recipeCount` (new category count is 0) |
| GET `/empty` | 200 | Array of CategoryBase: `name`, `id`, `groupId`, `slug`; **no count or timestamps** |
| POST `/merge` | 200 | CategoryOut for target, with resulting recipe count |
| GET `/{item_id}` | 200 | CategorySummary: **only** `id`, `slug`, `name` |
| PUT `/{item_id}` | 200 | CategorySummary: **only** `id`, `slug`, `name` |
| DELETE `/{item_id}` | 200 | JSON literal `null`, not an empty body or 204 |
| GET `/slug/{category_slug}` | 200 | `name`, `id`, `groupId: null`, `slug`, `recipes` with complete RecipeSummary objects |

JSON key order is immaterial. Do not copy tag response DTOs: category UUID reads/updates do not include recipes or groupId; category empty reads are schema-filtered camelCase objects; the category slug response deliberately has null groupId because Python uses `RecipeCategoryResponse.model_construct` without supplying it. Use a nullable DTO or map that retains this null (avoid `Map.of`).

POST/PUT accept required string `name` and ignore extra fields, including supplied IDs, groupId, slug and recipeCount. Model construction strips Python whitespace from name and derives slug with python-slugify; there is no category-specific length cap, recipe-style retry suffix, or nonempty-slug check. Whitespace-only names fail the ORM assertion, but punctuation-only nonblank names can produce an empty slug. Use `PyStr.strip` and `PySlugify`, not Java trim or the recipe creation slug validator. PUT reinitializes name/group/slug; unchanged values should not spuriously advance update_at. Preserve ID and created_at.

`item_id`, `fromId` and `toId` require UUID **version 4**, using `PyValidate.uuid4`, including its accepted alternate UUID spellings. Merge accepts camelCase aliases and snake_case field names; follow `ValidationErrors.bodyField` precedence. Distinguish malformed/non-v4 UUID validation errors from valid-but-absent IDs.

### Listing

Mirror the tag listing machinery with `categories` SQL names and `FilterEntities.CATEGORY`. Existing CATEGORY metadata already describes its columns, group and recipes relationships. Query parameters are camelCase: `orderBy`, `orderByNullPosition`, `orderDirection` (default desc), `queryFilter`, `paginationSeed`, `page` (1), `perPage` (50), plus optional `search`. Last repeated scalar value wins. Unknown query parameters are ignored.

Envelope uses snake_case `per_page` and `total_pages`, plus `page`, `total`, `items`, `next`, `previous`. Guides use relative **`/categories`**, not `/api/organizers/categories`. They come from `q.model_dump()`, retaining default parameters and rendering null values as `None`; **search and unknown query parameters are not included**. `PageRequest` already implements this organizer convention. Default order is created_at descending when search is absent. Preserve multiple order attributes, explicit directions/null placement, seeded random, relation filters, and Python's filter/order error details. Do not make recipe_count filterable just because it is projected.

`perPage=-1` means no limit and response per_page equals total; `page=-1` selects the last page; pages below 1 clamp to 1. Cover zero, other negative values, out-of-range pages and large integers against Python rather than adding validation constraints. Missing/empty random seed currently raises an unhandled exception in PaginationQuery dependency; organizer Java helper likewise produces 500. Search operates on category **name**, without recipe normalization: SQLite token/quoted phrase LIKE search; PostgreSQL unquoted fuzzy pg_trgm search at threshold 0.5 with distance ordering. Reuse SearchFilter and transactional threshold setup. Include quoted search, Unicode and wildcard characters in parity checks.

### Errors and validation ordering

Use shared request parsing/validation and annotate handlers with `@PythonEndpoint` pointing to `mealie/routes/organizers/controller_categories.py`. Current function/definition lines: get_all 40, create_one 52, get_all_empty 73, merge_categories 78, get_one 93, update_one 100, delete_one 122, get_one_by_slug 142. Recheck positions if Python source changes. Declare `PyRequestBody` before `AuthUser`; malformed JSON is parsed before authentication, then path/query/body field errors are aggregated in FastAPI order, then permission checks run. Preserve both production 422 detail arrays and development diagnostic bodies, JSON/UTF-8/content-type errors, and existing auth headers.

- Missing/cross-group GET by UUID, PUT, and slug GET: 404 with `{"detail":{"message":"Not found.","error":true,"exception":null}}`.
- Missing/cross-group DELETE: HttpRepo catches NoResultFound and returns 404 with message `An unexpected error occurred.` and exception `No row was found when one was required`. **Do not copy tags' bare 400 deletion behavior.**
- Blank create/update: 400 with ErrorResponse message `An unexpected error occurred.` and empty-string exception from AssertionError.
- Slug collision on create **or update**: 409, ErrorResponse message `This item already exists.`; other integrity failures: 409 with generic message. HttpRepo handles PUT failures, unlike TagService's intentionally unhandled PUT behavior.
- Other caught CRUD failures: follow HttpRepo's 400/404/409 classification and rollback. Unhandled merge failures are plain-text 500.
- Merge checks, after permission: identical IDs 400 `{"detail":"from_id and to_id must be different"}`; absent/cross-group source 404 `{"detail":"from_id category not found"}`; absent/cross-group target 404 `{"detail":"to_id category not found"}`. Check source before target.

Use `IntegrityViolation` to reproduce SQLAlchemy exception text on each engine. Extend error formatting for category INSERT, UPDATE and DELETE with the actual Python statement/parameter conventions captured by parity tests. Do not reuse tags table/constraint names or manufacture unrelated attempted values. Nondeterministic UUID/timestamp fragments can be normalized in tests, but error class, columns, constraint names, SQL and parameter structure must remain correct. Capture Python responses first for any ambiguous database exception path.

## Persistence and service design

1. Add `CategoryController`, `CategoryService`, `CategoryRepository` under Java `organizers`; add `CategoryRow`, `CategoryMapper` and mapper XML under existing persistence/resource directories. Use constructor injection and existing MyBatis registration; no new persistence framework/dependencies. Prefer small category-specific DTOs for the three response shapes. Avoid a broad tags/tools refactor in this migration.
2. Adapt TagRepository's pagination/search/query implementation to CATEGORY, binding values through SqlFragment. Mapper count must count scoped category rows. Project recipe_count with correlated `count(recipes_to_categories.recipe_id)` by category ID, like RepositoryCategories._query; it counts association rows, not household-visible recipes. Empty uses NOT EXISTS joined to actual recipes, matching `~Category.recipes.any()`, and has no explicit sort.
3. All externally selected category IDs/slugs must be looked up with group_id. Derive group from AuthUser, never request fields. Resolve both merge operands before writing. Add group predicates to mutations where practical even after scoped lookup. Same name/slug in different groups is legal; uniqueness is `(slug, group_id)` named `category_slug_group_id_key`.
4. Use UUIDv4 IDs and UTC microsecond timestamps. `SqlDialect.uuid` converts native Postgres UUID versus SQLite 32-character hex; timestamp/type handlers preserve SQLAlchemy storage (`YYYY-MM-DD HH:mm:ss.ffffff` on SQLite, naive UTC on Postgres). Never bind dashed UUID strings directly to SQLite columns. Keep portable LIMIT/OFFSET behavior, including SQLite LIMIT -1 when unlimited.
5. Put mutations in TransactionTemplate boundaries. Translate errors outside a rolled-back transaction. Publish events only after successful commit. Delete removes recipe-category links as SQLAlchemy's Category.recipes relationship does and deletes the category, leaving recipe content, timestamps and recipes intact. On failed deletes restore all removed links.
6. Merge updates source recipe links whose recipe is absent from target, deletes remaining source recipe links, then deletes source category, all atomically. Preserve target ID/name/slug and count the union without duplicate pairs; do not update recipe timestamps or target timestamp unnecessarily. Merge publishes **no** events.
7. Important legacy associations: `group_to_categories`, `plan_rules_to_categories`, `cookbooks_to_categories` reference categories without ON DELETE CASCADE. Their parent relationships are not reverse relationships on Category. Do **not** assume Python deletes or transfers these links. Before implementing deletion SQL, characterize Python delete and merge with each association separately on both engines, recording FK enforcement and post-failure state. Match Python's existing cleanup/failure behavior and rollback; do not silently migrate cookbook/rule filters or add cascades. SQLite may differ from PostgreSQL when FKs are not enforced. Never disable Postgres constraints to make tests pass.

### Slug lookup and recipes

Python first calls scoped HttpRepo.get_one(slug), then constructs a **group-scoped** recipe repository with household_id=None and calls `page_all(PaginationQuery(per_page=-1, query_filter='recipe_category.id IN ["<id>"]'))`. It includes recipes across households in the group (including private/locked recipes), excludes owners with no household as the recipe repository does, and orders recipes by default created_at descending. This is different from tags' unsorted relationship loader.

Implement a public, narrowly scoped recipe service/repository operation for category summaries: select group recipe IDs linked to this category with the above default order and eligibility predicates, then call existing `RecipeRepository.summaries(ids, groupId)` inside a read transaction. This method is already public and batches organizers/household tool data. Alternatively expose a narrow internal listing API; RecipeListQuery/select are package-private today, so an organizer service cannot just call them. Avoid fabricating an HTTP request or forwarding requests to Python. No pagination envelope belongs inside `recipes`.

Verify complete RecipeSummary parity: householdId from owner, numeric defaults, orgURL spelling, date/time formatting, tools and householdsWithTool, category/tag/tool arrays, and nested recipeCount values. A subtle possible session-identity effect: the slug category was previously loaded with its count in the same Python session, so that category's count inside recipes may differ from the zero used for other nested organizers. Capture a fixture with multiple recipes/categories; if present, override only the selected category's nested count in this operation, leaving generic recipe listing behavior intact. Do not reuse TagMapper.recipeRows and its different ordering/projection wholesale. Test unknown slug 404 and a valid category with no recipes returning an empty array.

## Notifications

Reuse EventBridge after successful create/update/delete. Send event types `category_created`, `category_updated`, `category_deleted`; documentData `{documentType:"category", operation:"create"|"update"|"delete", categoryId:<id>}`; actor integrationId, category groupId, householdId null. Message keys are `notifications.generic-created-with-url`, `notifications.generic-updated-with-url`, `notifications.generic-deleted`. Include name; URL descriptor type `category` and slug for create/update; omit URL for delete. Forward Accept-Language.

Extend `mealie/routes/internal/controller_events.py` by importing EventCategoryData and registering `"category"` in DOCUMENT_TYPES and `urls.category_url` in URL_BUILDERS. This small adapter extension is the only planned Python feature change. Keep HMAC, freshness, validation, group notification fanout and gateway blocks unchanged. This is the generic `/api/internal/events` bridge, not the separate recipe-created/updated adapter and dedicated key. Notifications remain asynchronous/best effort and cannot undo committed category writes. Never publish on errors or merge. Test actual notification delivery to subscribed households, localization, API-token integration metadata and delivery failure behavior.

Use isolated temporary SQLite files and uniquely named disposable Postgres databases; refuse occupied ports and nonempty fixture databases. Record responses, stored state, notifications, backend routing and service logs.
2. Capture a Python baseline before assuming questionable edge behavior: nested slug counts, legacy associations, UUID spellings, SQL error messages, unsupported methods/Allow headers and extreme pagination. 4. Run live parity on **both** engines, including production and development validation modes. Matrix must include all eight routes, positive and negative auth (cookie and API token included), complete slug summaries, all list query modes and links, mutation errors and state rollback, legacy associations, actual notifications, no events on merge/errors and event-delivery outage. 5. Add deterministic read-only category cases to `dev/rebuild/diff_cases.json` (listing, empty, pagination, sorting, search/filter and errors). 7. After endpoint parity passes, add a segment-bounded Caddy path matcher selecting `/api/organizers/categories` **and** `/api/organizers/categories/*` for Java. This covers all methods for this endpoint group, including Java's compatible trailing-slash redirects. Avoid an overbroad `/categories*` prefix that captures sibling names. Keep named matchers disjoint, retain tags/tools and recipe routing and both internal-event blocking rules. Update gateway documentation with coverage and rollback (remove matcher/proxy).
8. Exercise the actual Caddyfile in the isolated harness. Assert `X-Mealie-Backend: java` for category operations, redirects and error cases; Python for explore organizers, other unmigrated organizers and unrelated writes; 404 at both internal prefixes. Verify category reads and native mutations with Python category handlers deliberately disabled but the event adapter still running. Then stop Python to prove category persistence/reads are native and writes still commit despite unavailable notifications. Category slug summaries must also work without Python.
9. UI smoke test against the gateway: category page list/counts, create, rename, delete, merge and delete-unused; recipe category options and filtering; same-group household access. Confirm Network responses use Java and retained recipe edits still use Python. No frontend changes should be necessary.

## Completion criteria

The complete category group is served by Java with unchanged shapes, validation/errors, group isolation, list/search/filter/pagination behavior and mutation effects. Both SQLite and real PostgreSQL parity matrices pass, including overlap merges and rollback. Events reach the original subscribers with matching category URLs and translations. Gateway boundaries and rollback are documented, existing migrated endpoints still pass their relevant regressions, and reports identify the tested artifact and any precisely explained engine-specific legacy behavior. Do not declare completion based only on SQLite MockMvc tests or read-only diff results.
